# 04 模型策略與自訓路線

本文件說明 POC 階段的模型選擇、未來自行訓練模型的路線，以及參考文獻。

---

## 1. POC 階段的模型策略

POC 階段不自行訓練模型，原因如下：

- 主辦方提供的照片數量有限，不足以訓練可靠的專用模型。
- 大型視覺語言模型（VLM）可以零樣本（zero-shot）或少樣本（few-shot）直接使用，最快做出成果。
- POC 的重點是驗證流程與服務設計，不是模型本身。

| 功能 | POC 使用的方法 |
|---|---|
| 模糊、曝光 | OpenCV 規則 |
| 車輛偵測、距離判斷 | 預訓練 YOLO（COCO 的 car 類別） |
| 車牌 | 預訓練偵測模型加 PaddleOCR |
| 拍攝角度、遮擋 | 小型 VLM（例如 Claude Haiku 4.5） |
| 新車損比對 | 大型 VLM（例如 Claude Opus 5.5），加上影像對齊 |
| 整潔度、遺留物 | 大型 VLM，加上評分準則與範例 |

## 2. 為什麼未來要自訓

| 考量 | 只用 VLM API | 加入自訓模型後 |
|---|---|---|
| 即時層延遲 | 1 至 3 秒，且受網路影響 | 手機端 100 ms 以內 |
| 成本 | 每張照片都要付費呼叫 | 大部分照片由小模型處理，只有不確定的送 VLM |
| 資料外傳 | 照片需送到外部服務 | 可在自有環境內處理 |
| 針對性 | 通用模型，不了解 iRent 車型與拍攝規範 | 用 iRent 自己的資料訓練，更貼近實際情境 |

## 3. 三階段演進路線

| 階段 | 做法 | 目的 | 產出 |
|---|---|---|---|
| A. VLM 先行 | 規則加上 VLM API 上線 | 快速提供服務並累積資料 | 照片、VLM 判斷結果、人工確認結果 |
| B. 蒸餾與標註 | 以 VLM 輸出作為初步標籤（pseudo-label），人工抽查修正；人工駁回的案例優先標註 | 低成本建立訓練資料集 | 標註資料集 |
| C. 自訓小模型 | 訓練各任務專用小模型並部署；VLM 改為第二層複核 | 降低延遲與成本 | 手機端與伺服器端模型 |

階段 C 的串接方式（cascade）：

```
照片 --> 自訓小模型 --> 信心高：直接採用結果
                     --> 信心低：送大型 VLM 複核 --> 仍不確定：人工確認
```

## 4. 各任務的自訓模型建議

| 任務 | 模型類型 | 建議起點 | 部署位置 |
|---|---|---|---|
| 拍攝角度分類 | 影像分類 | MobileNetV3 或 EfficientNet-Lite，以 ImageNet 預訓練權重微調 | 手機端 |
| 照片品質（模糊、遮擋、反光等） | 多標籤分類 | 和角度分類共用 backbone，另接一個多標籤 head | 手機端 |
| 車牌偵測 | 物件偵測加 OCR | YOLO nano 或 small，以台灣車牌資料微調；OCR 用 PaddleOCR | 手機端或伺服器 |
| 車損偵測 | 物件偵測或實例分割 | YOLO-seg 或 Mask R-CNN；先以 CarDD 公開資料集訓練，再以 iRent 資料微調 | 伺服器 |
| 取還車變化偵測 | Siamese 變化偵測 | 對齊後的照片對輸入 Siamese 網路或 ChangeFormer 類架構 | 伺服器 |
| 整潔度分類 | 影像分類 | DINOv2 特徵加線性分類器（linear probe），少量資料即可訓練 | 伺服器 |
| 遺留物偵測 | 開放詞彙偵測 | Grounding DINO 零樣本起步，累積資料後再微調 | 伺服器 |
| 自訓 VLM（選用） | 視覺語言模型微調 | 開源 VLM（例如 Qwen2-VL 系列）加 LoRA | 伺服器（需 GPU） |

## 5. 資料與訓練注意事項

### 5.1 標註

- 標註工具：Label Studio 或 CVAT。
- 先寫好標註規範（例如什麼程度算「刮傷」、什麼算「髒汙」），多人標註時定期檢查一致性。
- 標註項目：拍攝角度、品質問題標籤、車牌框、車損框與類型、整潔度等級、遺留物框。

### 5.2 資料切分

以「車輛」或「訂單」為單位切分訓練、驗證、測試集，不可隨機切照片。否則同一台車的照片同時出現在訓練集與測試集，評估分數會虛高。

### 5.3 類別不平衡

車損與髒汙是少數類別。處理方式：oversampling、focal loss、資料增強（亮度、角度、裁切），以及針對性地收集異常照片。

### 5.4 評估指標

| 任務 | 主要指標 | 補充指標 |
|---|---|---|
| 照片品質 | 各問題類別的 precision、recall | p50、p95 延遲；上線後的重拍率 |
| 拍攝角度 | 準確率、混淆矩陣 | 延遲 |
| 車損 | recall（優先） | 每 100 次還車的誤報次數；位置正確率 |
| 整潔度 | 混淆矩陣 | 「髒汙被判為乾淨」的比例（最需要避免） |

### 5.5 手機端部署

- 量化：INT8 post-training quantization，必要時使用 quantization-aware training。
- 格式：Android 用 TFLite，iOS 用 Core ML。
- 在中低階手機上實測延遲與耗電。

### 5.6 持續改進

- 上線後持續收集人工確認與駁回的結果。
- 定期挑出模型最不確定、或被人工駁回的案例優先標註（active learning），重新訓練。
- 新模型上線前，先和舊模型在同一測試集上比較，並以小比例流量試行。
