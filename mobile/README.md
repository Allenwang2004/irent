# 取還車拍照模擬（手機網頁）

用網頁模擬 iRent App 的取車、還車拍照流程，示範拍照當下的即時品質檢查。黑客松展示用，不需要登入。

## 流程

1. 營運後台（`web/` 的「車輛」頁）新增車輛，用手機打開登錄連結拍基準照片（卡片＋ 6 個角度）
2. 首頁只列出已登錄完成的車：可借用的車「我要取車」，租用中的車「我要還車」
3. 取車、還車都依 iRent 的順序拍：加油卡／停車卡、前座、後座、左前、右前、左後、右後
4. 頁面裡直接開即時相機（`getUserMedia`），畫面上疊：
   - 對齊框線（`guides.tsx`）
   - 上一次同角度的照片，半透明（可隱藏）。取車疊這台車上一次的紀錄（上次還車或登錄照），還車疊這筆租用的取車照，和 worker 比對用的基準相同
   - 每 0.5 秒檢查一次亮度和清晰度，按快門前就提示「太暗」「模糊」
   沒有相機權限或瀏覽器不支援時，自動改用手機的相機 App。也可以「從相簿選擇」準備好的照片
5. 每張拍完立刻在瀏覽器裡檢查清晰度、亮度、反光
   - 不合格：只能重拍
   - 有提醒：可以重拍或仍使用
6. 必拍照片之後可以（不強制）拍這台車的已知車損特寫，以及其他損傷（取車：發現的既有損傷；還車：自行承認的損傷）
7. 照片縮到長邊 1280px，用伺服器發的簽名網址直接上傳到 Supabase Storage，確認後送出；實驗室的 VLM worker 分析後，預警出現在營運後台

## 品質檢查門檻

在 `src/lib/quality.ts`，用資料集 1,200 張真實還車照片校準：

| 檢查 | 不合格 | 提醒 |
| --- | --- | --- |
| 清晰度（Laplacian 變異數，長邊 640） | < 20 | < 45 |
| 平均亮度 | < 20 | < 35 |
| 過曝面積 | > 30% | > 15% |

真實照片約 2 到 3% 會被判為不合格。目前只檢查畫質，還不會判斷拍攝角度或車牌。

## 本機開發

```bash
cd mobile
npm install
cp .env.example .env.local   # 填入跟 web/ 同一個 Supabase 專案的 URL 和 Secret key
npm run dev                  # 預設 http://localhost:3000，手機上的網頁相機需要 HTTPS（部署到 Vercel）；本機 localhost 可用電腦的視訊鏡頭
```

資料表和 Storage bucket 由 repo 根目錄的 `supabase/04_inspections.sql` 建立。
